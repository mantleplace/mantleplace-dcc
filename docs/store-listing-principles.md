# Store listing principles

Every host plugin's storefront listing follows one skeleton, so a curator who has read one listing
knows where to look in the next. What differs is the host's own vocabulary and workflow, which stay
tailored to that host's audience. A listing states only what its release does; the README and release
notes own the facts.

## Section order

1. **Title.** `Mantle Place - Real-World Terrain, Imagery, Buildings, Roads and more`. No host product
   name or logo if the store's rules forbid it.
2. **Short description.** `Bring a real site into <the host's own noun>: terrain, aerial imagery,
   buildings, roads, trees and more, from a bundle you ordered or downloaded. A bundle import needs no
   account.`
3. **Long description**, in this order:
   1. Opening: one or two sentences. Mantle Place turns open geospatial data for a site into a bundle;
      this plugin brings that bundle into the host, placed at the site's real position, in the host's
      terms (a level, a project).
   2. **What an import brings in.** One bulleted list in the host's terms. The last bullet is
      `And more, depending on what the bundle holds.` Every list of data layers or of what is imported
      ends with "and more"; none reads as exhaustive.
   3. **Watch it work.** The import window's steps, their states and Cancel.
   4. **MPB 3.0 beside 2.x.** One shared sentence on the bundle formats.
   5. **Choose a level before you download.** Max, Med and Min, with sizes, for a 3.0 order.
   6. Host-specific sections, each a bold lead-in: the host's own surfaces and workflow (a ribbon tab,
      a vault window, streamed terrain, and so on).
   7. **Credit and sharing.** The credit text, how data under the ODbL is kept apart, and the
      hand-over command.
   8. **Yours to keep.** The bundle is downloaded to the curator, and the import is ordinary host
      content in their project.
   9. **Account and sign-in.** A bundle import needs no account and no sign-in; ordering a bundle needs
      a mantle.place account.
   10. **Support.** The feedback form at `https://mantle.place/feedback`, which needs no account.
4. **What is new in `<version>`.** A short list of the release's changes.
5. **Technical details.** Bullets in this order: Compatibility (one line, the only place the exact
   host version is stated), Platform, Network, then host-specific bullets, then Distribution.
6. **Reviewer instructions.** A no-account walk-through from the public samples page, last, in the
   listing or in a file of its own.

## Principles

- **The host's name, not its minor version, in prose.** Headline and descriptive text say the host
  (for Unreal, Unreal Engine). The exact supported version appears once, on the Compatibility line.
- **Lists end with "and more".** Imported layers, data layers, anything enumerated.
- **Human copy says curator and bundle.** Never "artifact" or "user".
- **No price, free-area size or free-build limit.** Pricing lives on the pricing page.
- **One home for each fact.** If the README or release notes own it, the listing words it for a store
  page and does not restate the detail.
- **No claim beyond the release.** A feature that is not shipped is not in the listing.
